# RoboMaster 2026 雷达站无线电规则变更说明（对齐全国赛新版）

> **文档目的**：说明从「规则手册 V1.4.2 + 通信协议 V1.3.0」到「规则手册 V2.1.0 + 通信协议 V2.0.0」的无线电相关改动；并解释这些改动对 **PlutoSDR 硬件** 与 **解调软件** 的实际影响。  
> **读者假设**：熟悉比赛机制，无线电基础知识较薄弱。  
> **结论先行**：**不需要换更高端的 SDR 硬件。** PlutoSDR 完全够用。需要改的是 GNU Radio / 解码脚本中的参数与协议解析。

---

## 0. 一句话结论：硬件会更吃力吗？

| 问题 | 答案 |
|------|------|
| PlutoSDR 采样率要不要提高？ | **不用。** 官方仍写 Sample Rate = 1 MHz |
| RF 带宽 / 中心频点变了吗？ | **没变。** 最大干扰波带宽仍是 0.94 MHz |
| 接收灵敏度 / 动态范围要求更高了吗？ | **基本没有。** 发射功率表未改 |
| 真正变难的地方在哪？ | **软件**：SPS 52→47、Sensitivity 重算、`0x0A05` 帧变长 |

**为什么这么说？**

PlutoSDR 的“能力上限”主要由这些指标决定：

1. **能采多快**（采样率）：你们已经在用 1 Msps，新旧版官方发射端也是 1 Msps。  
2. **能看多宽**（模拟带宽）：最大信号带宽仍约 0.94 MHz，放在 1 MHz 采样里完全装得下。  
3. **能听多弱**（噪声系数 / 灵敏度）：发射功率没变，场地几何没因此变差。

新规则只是把每个符号占用的采样点数从 52 减到 47，相当于**同样 1 MHz 采样里，符号打得稍密一点**。对 Pluto 来说，这只是解调器参数变化，不是“硬件带宽不够”的问题。

## 1. 背景：雷达无线电在比什么？

比赛中，官方在双方雷达基座放置发射源，发出两类电磁波：

| 类型 | 作用 | 空口 Access Code |
|------|------|------------------|
| **信息波（广播源）** | 携带对方机器人位置、血量、发弹量、增益等 | `0x2F6F4C74B914492E` |
| **干扰波** | 几乎无有效业务数据，只夹带对方自定义的 6 位密钥 | `0x16E8D377151C712D` |

你们的任务本质是：

1. 用 PlutoSDR 收到 433 MHz 附近的 GFSK 信号；  
2. 解调成比特流；  
3. 按空口帧切出 Payload；  
4. 再按裁判系统串口协议拼出 `0x0A01`～`0x0A06`。

新旧版差异，主要落在第 2 步（解调参数）和第 4 步（`0x0A05` 载荷）。

## 2. 需要先懂的几个名词（尽量白话）

### 2.1 采样率（Sample Rate）

把连续无线电波形“拍成照片”的速度。  
官方与你们工程均为：

\[
\text{Sample Rate} = 1\,\text{MHz} = 每秒 100 万个复数采样点
\]

**新旧版都没改。** 所以 Pluto 不需要为了新规则去冲 2 MHz / 4 MHz。

### 2.2 SPS（Samples Per Symbol，每符号采样数）

GFSK 里，一个“符号”在 2-GFSK 下就是 1 bit。  
SPS 表示：**发 1 bit 要用掉多少个采样点**。

\[
\text{符号率（波特率）} = \frac{\text{Sample Rate}}{\text{SPS}}
\]

| 版本 | SPS | 符号率 | 1 bit 持续时间 |
|------|-----|--------|----------------|
| 旧版 | 52 | ≈ 19.23 kbaud | 52 μs |
| 新版 | **47** | ≈ **21.28 kbaud** | **47 μs** |

**影响原理：**

- 解调器内部要按“每 N 个采样点判一次 bit”来工作。  
- 若官方已改成 SPS=47，你仍用 52，判位时刻会逐渐错位 → CRC 失败、密钥解不出、信息波丢包。  
- 这是**时钟/符号定时不匹配**，不是天线或板子坏了。

### 2.3 频偏 Δf 与 Sensitivity

2-GFSK 用“频率往上偏 / 往下偏”表示 bit 1 / bit 0。  
官方给出：

\[
\Delta f = \frac{B}{2} - \frac{\text{Sample Rate}}{\text{SPS}}
\]

\[
\text{Sensitivity} = \frac{2\pi \cdot \Delta f}{\text{Sample Rate}}\quad(\text{单位：rad/sample})
\]

其中 \(B\) 是该波源的 signal_bandwidth（规则表里的“带宽”）。

**影响原理：**

- GNU Radio 的 `gfsk_demod` / `gfsk_mod` 用 `sensitivity` 把“相位变化”映射回 bit。  
- SPS 变了以后，即使带宽 B 不变，\(\Delta f\) 也会变一点，Sensitivity 必须同步改。  
- 参数错了会出现：频谱上看得到峰，但解调误码率很高。

### 2.4 BT（高斯滤波参数）

GFSK 在变频前会过高斯滤波器，BT=0.35 控制“频谱有多圆滑”。  
**新旧版 BT 都是 0.35，不用改。**

### 2.5 空口帧 vs 协议帧

不要混：

| 层级 | 内容 | 是否变化 |
|------|------|----------|
| **空口包** | Access Code(8) + Header(4) + Payload(15) | 结构不变 |
| **协议帧** | `0xA5` + 长度 + seq + CRC8 + cmd_id + data + CRC16 | `0x0A05` 的 data 变长 |

空口仍是每 15 字节切一片发出；更大的协议帧会被切成更多空口包。

## 4. 详细改动与原理说明

### 4.1 【核心】SPS：52 → 47

**改了什么**  
所有波源（红蓝广播/一~三级干扰）的高斯滤波参数里，SPS 从 52 改为 47。

**为什么影响大**  
在固定 1 MHz 采样下：

- 旧：每秒约 19231 个 bit  
- 新：每秒约 21277 个 bit  

比特变“更快了一点”（约 **+10.6%**）。

对接收机来说：

1. **符号同步点变了**：仍按 52 取点会“踩不准”。  
2. **包时长变短**：216 bit 的空口包从 11.23 ms 变为 10.15 ms。  
3. **CPU 负载略增**：同样时间内要判更多 bit，但对现代工控机/笔记本可忽略；Pluto USB 吞吐仍是约 1 Msps，**瓶颈不在 USB**。

**对 PlutoSDR**  
- RX 采样率继续 1e6 即可。  
- 不必为了 SPS=47 去提高采样率。  
- 必须改 GNU Radio：`samples_per_symbol=47`。

> 你们仓库现状（需对齐）：  
> `competition/jamming/tx_radio.py`、`competition/info/tx_radio.py` 仍为 `samples_per_symbol=52`。

---

### 4.2 【核心】Sensitivity 全表更新

带宽 B 与功率未变，但因 SPS 变了，公式里的 \(\Delta f\) 变了，Sensitivity 必须重算。

#### 4.2.1 完整对照表

| 波源 | 中心频点 (MHz) | 带宽 B (MHz) | 功率 (dBm) | 旧 Sensitivity | 新 Sensitivity |
|------|----------------|--------------|------------|----------------|----------------|
| 红方广播源 | 433.2 | 0.54 | -60 | 1.5756 | **1.5628** |
| 红方一级干扰 | 432.2 | 0.94 | -10 | 2.8323 | **2.8194** |
| 红方二级干扰 | 432.5 | 0.86 | -10 | 2.5809 | **2.5681** |
| 红方三级干扰 | 432.8 | 0.25 | -10 | 0.6646 | **0.6517** |
| 蓝方广播源 | 433.92 | 0.54 | -60 | 1.5756 | **1.5628** |
| 蓝方一级干扰 | 434.92 | 0.94 | -10 | 2.8323 | **2.8194** |
| 蓝方二级干扰 | 434.62 | 0.86 | -10 | 2.5809 | **2.5681** |
| 蓝方三级干扰 | 434.32 | 0.25 | -10 | 0.6646 | **0.6517** |

#### 4.2.2 用广播源验算（帮助建立直觉）

旧版 SPS=52，B=0.54 MHz：

\[
\Delta f = 0.27\times10^6 - \frac{10^6}{52} \approx 250769\,\text{Hz}
\]
\[
\text{Sens} = 2\pi\cdot250769/10^6 \approx 1.5756
\]

新版 SPS=47：

\[
\Delta f = 0.27\times10^6 - \frac{10^6}{47} \approx 248723\,\text{Hz}
\]
\[
\text{Sens} = 2\pi\cdot248723/10^6 \approx 1.5628
\]

数值变化看起来不大（约 0.8%），但 GFSK 解调对这个参数敏感——**必须用新值**。

**对 PlutoSDR**  
硬件无关；改 `target_sens` / `FREQ_MAP` 即可。  
你们 `jamming_decoder_f1.py` 里仍是旧 Sensitivity，需要更新。

---

### 4.3 时域特征变化（附录 1）

以红方广播源为例：

| 特征 | 旧版 | 新版 | 含义 |
|------|------|------|------|
| 每 bit 持续时间 | 52 μs | **47 μs** | 1 bit 在时间轴上更短 |
| 每包持续时间 | 11.23 ms | **10.15 ms** | 216 bit × Tb |
| bit=1 瞬时频偏 | +250769 Hz | **+248723 Hz** | 与 Δf 一致 |
| bit=0 瞬时频偏 | -250769 Hz | **-248723 Hz** | 同上 |
| 高斯滤波 3dB 带宽 | ≈6731 Hz | **≈7447 Hz** | BT/Tb，Tb 变小则 3dB 带宽略升 |

**原理补充：**  
高斯滤波的 3dB 带宽近似 \(BT / T_b\)。\(T_b\) 从 52 μs 变 47 μs，滤波器在频率轴上略“变宽”，但这是发射成型的结果，不是要求你把 Pluto 带宽调大。

**对 PlutoSDR**  
RX 模拟带宽继续覆盖最大 0.94 MHz 信号即可（你们常用 source bandwidth=1e6，足够）。

---

### 4.4 信息波推送速率：1350 → 1400 byte/s

| 波源 | 旧速率 | 新速率 | 内容 |
|------|--------|--------|------|
| 信息波 | 1350 B/s | **1400 B/s** | `0x0A01`～`0x0A05`（10 Hz） |
| 干扰波 | 1350 B/s | 1350 B/s | `0x0A06`（10 Hz）+ 随机填充 |

**原因（可精确对上）：**  
`0x0A05` 从 36 字节增到 41 字节 → 每秒多 \(5\times10=50\) 字节 → 1350+50=1400。

**原理补充：**  
这是应用层有效载荷吞吐，不是 RF 采样率。空口仍按 15 字节切片连续发；只是信息波有效数据略多一点。

**对 PlutoSDR**  
无硬件压力。注意软件侧环形缓冲/统计阈值别写死成 1350。

---

### 4.5 【协议核心】`0x0A05`：36 → 41 字节

这是通信协议 V2.0.0 明确修订的无线链路命令。

#### 4.5.1 不变部分（offset 0～34）

各兵种回血 / 冷却 / 防御 / 负防御 / 攻击增益字段布局与旧版一致（到哨兵攻击增益为止）。

#### 4.5.2 变化 1：哨兵姿态枚举扩展（offset 35）

| 值 | 旧版含义 | 新版含义 |
|----|----------|----------|
| 1 | 进攻 | 进攻 |
| 2 | 防御 | 防御 |
| 3 | 移动 | 移动 |
| **4** | （无） | **强化进攻** |
| **5** | （无） | **强化防御** |
| **6** | （无） | **强化移动** |

#### 4.5.3 变化 2：新增“主要状态”5 字节（offset 36～40）

| 偏移 | 字段 |
|------|------|
| 36 | 对方英雄主要状态 |
| 37 | 对方工程主要状态 |
| 38 | 对方 3 号步兵主要状态 |
| 39 | 对方 4 号步兵主要状态 |
| 40 | 对方哨兵主要状态 |

取值约定：

| 值 | 含义 |
|----|------|
| 0 | 存活 |
| 1 | 战亡 |
| 2 | 无敌但不虚弱 |
| 3 | 无敌且虚弱 |

说明：异常离线不影响此处判断。

**原理补充（为什么这会影响无线电？）**  
RF 层只负责把比特收回来；但你们重组裁判帧时，若仍按 `data_length=36` 去切 `0x0A05`，会：

- CRC16 对不齐；  
- 后续 `0x0A01` 等帧边界错乱；  
- 表现为“有时解得出、有时全乱”。

这是**帧定界错误**，常被误判成“信号不好 / 硬件不行”。

**对 PlutoSDR**  
纯软件解析问题。信息波解码脚本必须改。

---

### 4.6 `0x0A01`～`0x0A04`、`0x0A06`：无实质变化

| 命令 | 长度 | 含义 | 新旧 |
|------|------|------|------|
| 0x0A01 | 24 | 对方各机器人坐标 (cm) | 不变 |
| 0x0A02 | 12 | 对方血量 | 不变 |
| 0x0A03 | 10 | 对方允许发弹量 | 不变 |
| 0x0A04 | 8 | 金币与占领/交互状态位图 | 不变 |
| 0x0A06 | 6 | 干扰波 6 位 ASCII 密钥 | 不变 |

Access Code、Header（双份 0x000F）、15 字节 Payload 切片规则均不变。

---

### 4.7 `0x0121` 密钥上报：文档修正，结构本就 8 字节

| 项目 | 旧版总览表 | 新版总览表 | 两侧详细结构 |
|------|------------|------------|--------------|
| 内容长度 | 写 1 | 写 **8** | 均为 8 字节 |

结构：

```text
byte0     : radar_cmd          // 双倍易伤触发计数
byte1     : password_cmd       // 1=更新己方密钥, 2=验证对方密钥
byte2..7  : password[6]        // ASCII 字母/数字
```

逻辑（未变）：

- 仅开局或对方破解成功导致己方干扰难度升级时，可修改己方密钥；  
- `password_cmd=2` 验证成功后 10 秒内再次更新无效。

**对无线电**：不改空口；只影响雷达站通过常规链路向服务器交密钥的报文长度写法。

## 5. 明确未改动的射频要素（可放心复用）

以下内容新旧版一致，天线/前端设计可继续用：

1. **调制**：2-GFSK；映射 `0→-1，1→+1`  
2. **Sample Rate**：1 MHz  
3. **BT**：0.35  
4. **中心频点 / 带宽 / 功率表**（除 SPS/Sensitivity 外）  
5. **Access Code**  
   - 信息波：`0x2F6F4C74B914492E`  
   - 干扰波：`0x16E8D377151C712D`  
   - 红蓝相同  
6. **空口帧**：8 + 4 + 15 字节；无独立前导码；无白化；无 FEC  
7. **机制**：干扰波难度 1→3、破解提升对方难度、难度更高方封锁易伤等文字逻辑

## 6. 专门回答：PlutoSDR 够不够？会不会“更吃硬件”？

### 6.1 结论

**够。不会因为新规则而必须升级硬件。**

### 6.2 分项评估

| 硬件维度 | 旧规则需求 | 新规则需求 | PlutoSDR（典型） | 是否吃紧 |
|----------|------------|------------|------------------|----------|
| RX 采样率 | 1 Msps | 1 Msps | 常用可达可达数 Msps | 轻松 |
| 信号带宽 | ≤0.94 MHz | ≤0.94 MHz | 可配 ≥1 MHz BW | 轻松 |
| 调谐频率 | ~432–435 MHz | 同左 | 覆盖 325–3800 MHz | 轻松 |
| USB 吞吐 | ~1 Msps IQ | 同左 | USB2 足够 | 轻松 |
| 本振精度/漂移 | GFSK 窄带 | 略快一点的符号率 | 通常可接受；注意预热 | 与旧版同级 |
| 前端动态范围 | 广播 -60 dBm + 干扰 -10 dBm 同场 | 同左 | 需合理增益，非新问题 | **本来就难，但不是新规则造成的** |

### 6.3 新规则真正增加的“难度”在哪里？

1. **参数对齐成本**：漏改 SPS/Sensitivity → 看起来像硬件坏了。  
2. **协议解析成本**：`0x0A05` 变长导致组帧错误。  
3. **符号率 +10.6%**：对定时恢复稍敏感一点；在 SNR 很差时误码可能略升，但远不到“必须换 USRP”的程度。  
4. **同场强弱信号**（-60 dBm 广播 vs -10 dBm 干扰）仍是最大工程难点——**这在旧版就存在**，不是 V2 新引入。

### 6.4 什么情况下才需要考虑更强硬件？

以下情况与“规则从 1.4.2 升到 2.1.0”**无关**，属于另一类升级动机：

- 想单台设备同时宽开接收红+蓝全部频点并做高阶干扰抑制；  
- 需要极低相位噪声 / 外置时钟做科研级测量；  
- 需要远高于 1 Msps 做频谱感知算法。

对“按官方参数解调信息波/干扰波并交密钥”的比赛目标，**PlutoSDR + 正确参数即可。**

### 7.4 密钥上报

## 8. 推荐回归测试顺序

1. **实验室环回**：Pluto TX 用新 SPS=47 / 新 Sensitivity 自发自收，确认 Access Code + Header + CRC 通过。  
2. **只改 SPS、不改 Sensitivity**：刻意做错，观察误码——建立“参数错 ≠ 硬件差”的直觉。  
3. **信息波**：注入含 41 字节 `0x0A05` 的模拟流，确认组帧不再错位。  
4. **干扰波扫频**：三级频点 + 新 Sensitivity，确认密钥 ASCII 稳定。  
5. **联调**：破解密钥 → `0x0121` 上报 → 观察对方难度升级。
