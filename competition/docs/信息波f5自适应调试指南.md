# 信息波 f5 自适应调试指南

## 目标与边界

f5 面向**现场环境不确定**（干扰强弱变化、信息波约 -40～-60 dB）时，希望少人工换档。它不改变官方空口参数：

- 采样率 1 MHz，SPS 47，Sensitivity 1.5628
- 频点：红 433.2 MHz / 蓝 433.92 MHz
- Access / Header `00 0F 00 0F` / 15B Payload / CRC / `0x0A01`～`0x0A05` 不变
- ROS 话题仍为 `radio/info/{position,hp,ammo,macro,buff}`
- Header **严格匹配**；正式话题只发布 CRC 有效帧

相对 f4 的新增：

1. 优先使用 `symbol_sync(M&M + MMSE)`（无则回退 `clock_recovery_mm`）
2. 解码器按统计窗口 **热切换 RF/FIR/增益档**
3. Access 汉明上限随假同步迹象 **2↔4 自适应**
4. 比特缓冲加长到约 18 万 bit

## 启动

默认自适应：

```bash
INFO_F5_PROFILE=auto python3 competition/info/info_decoder_f5.py
```

固定档（关闭 RF 自动轮换，仍可保留 Access 本地自适应）：

```bash
INFO_F5_PROFILE=baseline python3 competition/info/info_decoder_f5.py
INFO_F5_PROFILE=weak_fixed python3 competition/info/info_decoder_f5.py
INFO_F5_AUTO_TUNE=0 INFO_F5_PROFILE=auto python3 competition/info/info_decoder_f5.py
```

手动分启：

```bash
RM_ENABLE_GRC_WATCHDOG=0 INFO_F5_PROFILE=auto \
  python3 competition/info/tx_radio5.py

RM_ENABLE_GRC_WATCHDOG=0 INFO_F5_PROFILE=auto \
  python3 competition/info/info_decoder_f5.py
```

同一时间不要与 f3/f4 共用 Pluto、UDP `14346`、RPC `8081`。

## 运行时档位（可热切换）

| tune | 意图 | RF BW | gain | FIR cutoff/transition |
|------|------|-------|------|------------------------|
| balanced | 默认现场 | 600k | 35 | 260/60 |
| wide_fir | 边带/滤波过窄 | 700k | 35 | 280/70 |
| weak_boost | 偏弱信号 | 600k | 40 | 260/60 |
| narrow | 强邻道干扰 | 540k | 30 | 255/40 |
| desense | 疑似削顶 | 600k | 25 | 260/20 |
| open | 干净信道试探 | 1000k | 40 | 300/50 |

**不会热切换**：SPS、Sensitivity、判决域 DC、平滑长度、时钟环 `gain_mu`（这些属启动拓扑）。

## 自适应逻辑（白话）

每 2 秒看一眼统计：

1. **有有效帧** → 保持当前档；连续 3 个好窗口进入 `locked`
2. **locked 后超过约 10s 无帧** → 重新 `explore`
3. **UDP 很多但 AC=0** → 切 `desense`（怀疑 IQ 顶平）
4. **有 AC 无 Header** → 切 `wide_fir` / `weak_boost`
5. **有 Header 无完整帧** → 切 `weak_boost` / `narrow`
6. 其它长时间无帧 → 按 `balanced → wide_fir → weak_boost → narrow → desense → open` 轮换
7. 切档冷却默认 **6s**，避免来回抖
8. AC 很多、CRC16 失败多、有效帧为 0 → Access 收到 2；长期无 AC → 放回 4

日志关键字：`[f5-auto]`、`auto=...`、`tune=...`、`state=explore|locked`。

## 建议测试

每个场景至少 60s：

1. 无干扰 -40 dB：应较快 `locked` 在 balanced/open，帧率不差于 f3
2. -10 dB 干扰 + -40 dB 信息波：相对 f3/f4 回归
3. -10 dB 干扰 + -60 dB 信息波：观察是否自动走到 `weak_boost`/`narrow`
4. 人为把增益推到削顶：应出现 `desense`
5. `INFO_F5_AUTO_TUNE=0` 对照：确认自动逻辑不是唯一能解的路径

## 环境变量

| 变量 | 默认 | 含义 |
|------|------|------|
| `INFO_F5_PROFILE` | `auto` | `auto` / `baseline` / `weak_fixed` |
| `INFO_F5_AUTO_TUNE` | `1` | RF 自动轮换开关 |
| `INFO_F5_ACCESS_HAMMING` | `4` | Access 放宽上限 |
| `INFO_F5_AUTO_COOLDOWN_S` | `6` | 切档冷却 |
| `INFO_F5_AUTO_SILENCE_S` | `4` | 开始探索的无帧时间 |
| `INFO_F5_RECORD` | `0` | 比特录制 |

## 已知限制

- 自动调参只动 RF/FIR/增益，救不了错误的 SPS/Sens。
- `symbol_sync` 依赖 GNU Radio 是否提供该块；没有则自动回退 M&M。
- 切档会清空比特缓冲，短时间帧率可能掉一下。
- 仍是硬判决接收机；Payload 内误码不能靠调增益修复。
- 纯内存自检不验证 Pluto/symbol_sync 实机效果。
