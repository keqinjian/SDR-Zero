# 信息波 f5 自适应调试指南

## 目标与边界

f5 面向**现场环境不确定**（干扰强弱变化、信息波约 -40～-60 dB）时，希望少人工换档。它不改变官方空口参数：

- 采样率 1 MHz，SPS 47，Sensitivity 1.5628
- 频点：红 433.2 MHz / 蓝 433.92 MHz
- Access / Header `00 0F 00 0F` / 15B Payload / CRC / `0x0A01`～`0x0A05` 不变
- ROS 话题仍为 `radio/info/{position,hp,ammo,macro,buff}`
- Header **严格匹配**；正式话题只发布 CRC 有效帧

相对 f4 的新增：

1. 优先使用 `symbol_sync(M&M + MMSE)`（无则回退 `clock_recovery_mm`）
2. 解码器按统计窗口 **热切换 RF/FIR/增益档**
3. Access 汉明上限随假同步迹象 **2↔4 自适应**
4. 比特缓冲加长到约 18 万 bit

## 启动

默认自适应（一条命令，不需要任何环境变量，会自动拉起 `tx_radio5.py`）：

```bash
python3 competition/info/info_decoder_f5.py
```

固定档（关闭 RF 自动轮换，仍保留 Access 本地自适应）：把 `tx_radio5_tunes.py` 的
`BOOT_PROFILE` 改成 `"weak_fixed"` 或 `"baseline"`，再把 `info_decoder_f5.py` 的
`ENABLE_AUTO_TUNE` 改成 `False`，然后照样一条命令启动。

手动分两个终端跑（想盯着频谱窗时）：把 `info_decoder_f5.py` 的
`ENABLE_GRC_WATCHDOG` 改成 `False`，然后

```bash
python3 competition/info/tx_radio5.py       # 终端 1
python3 competition/info/info_decoder_f5.py # 终端 2
```

同一时间不要与 f3/f4 共用 Pluto、UDP `14346`、RPC `8081`。

## 运行时档位（可热切换）

| tune | 意图 | RF BW | gain | FIR cutoff/transition |
|------|------|-------|------|------------------------|
| balanced | 默认现场（与 f3 balanced 完全对齐，A/B 基准） | 600k | 35 | 260/20 |
| weak_boost | 偏弱信号 | 600k | 45 | 260/20 |
| high_gain | 更弱信号 | 600k | 52 | 260/20 |
| max_gain | 极弱信号 | 600k | 58 | 260/20 |
| wide_fir | 边带/滤波过窄 | 700k | 45 | 280/60 |
| narrow | 强邻道干扰 | 540k | 45 | 255/15 |
| open | 干净信道试探 | 1000k | 45 | 300/50 |
| desense | 已确认削顶（**不在自动顺序里**，需手动指定） | 600k | 25 | 260/20 |

**不会热切换**：SPS、Sensitivity、判决域 DC、平滑长度、时钟环 `gain_mu`（这些属启动拓扑）。

> 为什么增益整体上调：现场频谱截图里，FIR 之前的原始 IQ 峰值只有约 -55 dBFS，
> 离满量程还有 50 dB 空余，说明 35~45 dB 根本没用满 ADC 动态范围，-60 dBm 级别的
> 信息波掉进了量化噪声。弱信号的正确方向是**加增益**，不是降增益。

## 自适应逻辑（白话）

每 2 秒看一眼统计：

1. **有有效帧** → 保持当前档；连续 3 个好窗口进入 `locked`
2. **locked 后超过约 10s 无帧** → 重新 `explore`
3. **有 AC 无 Header** → 切 `wide_fir` / `weak_boost`
4. **有 Header 无完整帧** → 沿增益阶梯往上爬一格
5. 其它长时间无帧 → 按 `balanced → weak_boost → high_gain → max_gain → wide_fir → narrow → open` 轮换
6. 切档冷却默认 **6s**，避免来回抖
7. AC 很多、CRC16 失败多、有效帧为 0 → Access 收到 2；长期无 AC → 放回 4

**f5 不做削顶判断。** 它唯一能看到的 `udp_bytes` 是判决之后的比特流量：哪怕天线上
什么都没有，噪声也会被硬判成 0/1 源源不断发过来，所以“UDP 很忙 + AC=0”是纯噪声的
常态，而不是削顶的证据。旧版据此切到 `desense`(25 dB) 会把本来就微弱的信息波彻底
埋掉。需要真正判定削顶请用 f6（有 IQ 探头）。

日志关键字：`[f5-auto]`、`auto=...`、`tune=...`、`state=explore|locked`。

## 建议测试

每个场景至少 60s：

1. 无干扰 -40 dB：应较快 `locked` 在 balanced/open，帧率不差于 f3
2. -10 dB 干扰 + -40 dB 信息波：相对 f3/f4 回归
3. -10 dB 干扰 + -60 dB 信息波：观察是否自动沿 `weak_boost → high_gain → max_gain` 往上爬
4. 人为把增益推到削顶：f5 无法自动识别，需手动切 `desense` 或改用 f6
5. `ENABLE_AUTO_TUNE = False` 对照：确认自动逻辑不是唯一能解的路径

## 已知限制

- 自动调参只动 RF/FIR/增益，救不了错误的 SPS/Sens。
- `symbol_sync` 依赖 GNU Radio 是否提供该块；没有则自动回退 M&M。
- 切档会清空比特缓冲，短时间帧率可能掉一下。
- 仍是硬判决接收机；Payload 内误码不能靠调增益修复。
- 纯内存自检不验证 Pluto/symbol_sync 实机效果。
