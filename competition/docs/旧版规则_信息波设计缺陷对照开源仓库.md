# 旧版规则下：本仓库 vs 开源仓库设计对照（信息波解不出的原因）

> 对照对象  
> - 本仓库：`SDR-Zero/competition`（双 Pluto：info + jamming）  
> - 开源：`RoboMaster-2026-Radar-Wireless-main`（单 SDR 时分接收）  
> 规则基准：**旧版**（SPS=52，Sensitivity 广播 1.5756，干扰 2.8323/2.5809/0.6646，`0x0A05`=36 字节）

**结论：开源仓库也是旧版规则。**

依据（`wireless_link/protocol.py`）：

因此：**用开源仓库对照你们旧程序是合理的；两边物理参数口径一致。**

## 1. 为什么干扰波能解、信息波解不出？（先抓本质）

### 1.1 协议结构不对称（最关键）

| | 干扰波 `0x0A06` | 信息波 `0x0A01`～`0x0A05` |
|--|-----------------|---------------------------|
| 单帧长度 | **恰好 15 字节** | 33 / 21 / 19 / 17 / 45 字节 |
| 占用空口包 | **1 个** Payload | 跨 **2～3 个** Payload；一整轮 **9 个**包（135 字节） |
| 容错 | 捞到 1 个好包就能 CRC 通过 | 必须连续多个包正确、按序拼接 |

开源仓库把这一点写死了：

```text
jamming round: 0x0A06 整帧 = 15 字节 = 1 个空口 Payload
information round: 5 个 cmd 拼起来 = 135 字节 = 9 个空口 Payload
```

**白话：**  
干扰波像“一张完整小纸条塞进一个信封”；  
信息波像“一封长信被撕成 9 个信封连续寄出”——中间丢 1 个，整封信就拼不起来。

你们两套解码器上层套路很像（模糊 Access Code → 抽 15 字节 → 找 `0xA5` → CRC），  
**这套套路天生偏向干扰波；信息波需要更高的“连续正确包率”。**

### 1.2 功率差 50 dB（物理层）

| 波源 | 功率 | 含义 |
|------|------|------|
| 广播/信息波 | **-60 dBm** | 极弱 |
| 干扰波 | **-10 dBm** | 很强 |

同一套“勉强够用”的解调，对干扰波可能偶尔成功，对信息波会系统性失败。  
这不是“信息波协议更难写”这么简单，而是 **SNR 差两个数量级**。

## 2. 开源仓库的设计思路（你们该学什么）

开源是 **单 SDR 时分**：`jam1 → jam2 → info`，按裁判加密等级切频。  
你们是 **双 SDR 并行**——架构可以保留，但应吸收其接收/解码质量措施。

### 2.1 接收链路（`pluto_rx.py` / `field_recording.py`）

| 开源做法 | 目的 |
|----------|------|
| Pluto 以 **2.083333 Msps** 采集，再有理数重采样到等效 1 Msps | 避开部分 USB/时钟问题，给符号同步留余量 |
| 实时链路：正交鉴频 + `symbol_sync`（M&M）+ slicer | 比裸 `gfsk_demod` 默认可控参数更清晰 |
| `gain_mu≈0.175`，`symbol_freq_error≈0.0048` | 符号时钟环更稳，并预留采样率误差 |
| 信息波建议 `dc_block` | 削弱 DC 偏置对 GFSK 判决的影响 |
| 信息波信道滤波约 **260 kHz**；干扰按等级换截止 | 抑制邻道（尤其 L3 干扰）进时钟恢复 |
| 手动增益约 **35**，且 info/jam 同一量级思路 | 弱信号优先保证前端增益 |

### 2.2 比特/空口层（`protocol.py` + `decoder.py`）

| 开源做法 | 目的 |
|----------|------|
| 默认 `air_bit_order = msb_all`，并可 auto 试多种端序 | 避免 bit 打包方向错导致“永远 CRC 不过” |
| **normal / inverted 双极性都解**，按出帧数选优 | GFSK 0/1 反了也能活 |
| Access Code：精确匹配，或 Hamming≤2 模糊 | 比“砍掉前 16 bit 再精确匹配”假阳性更低 |
| **强制校验 Header = `00 0F 00 0F`** | 假同步不进拼包缓冲 |
| 拼包：`payload` 顺序拼接 → 再扫裁判帧 | 正确重建跨包帧 |
| 信息波还有 **partial frame**（CRC 过且字段合理）兜底 | 整轮 135 字节凑不齐时，仍可能抽出坐标等 |
| CRC8 自动识别 legacy / reflected | 兼容不同录波 |

### 2.3 业务层

- 干扰：严格帧密钥 + 可选“按字节投票”的 recovered_key  
- 信息：输出坐标/经济/弹量，并标注来自 full 还是 partial  
- 与裁判串口联动切阶段（单 SDR 才需要；双 SDR 可简化）

## 3. 你们程序的设计缺陷（按严重程度）

### 缺陷 A【致命】信息波前端增益明显偏低

| | 干扰链路 | 信息链路 |
|--|----------|----------|
| 官方功率 | -10 dBm | **-60 dBm** |
| 你们 Pluto manual gain | **40** | **27** |

信息波比干扰波弱约 50 dB，增益反而更低——逻辑反了。

**影响：** 解调器输入 SNR 不足 → 误码率高 → 9 连包几乎不可能凑齐 → 统计永远是 0。  
干扰波因为太强，gain=40 仍可能解出，造成“干扰能解、信息不能”的假象。

**建议：** 信息波增益至少提到与开源相当（约 35～45），并在频谱上确认广播峰可见；必要时 AGC/调试增益曲线。关闭无用 TX。

---

### 缺陷 B【致命】信息波解码缺少极性翻转双搜

| | `jamming_decoder_f1.py` | `info_decoder_auto3.py` |
|--|-------------------------|-------------------------|
| 搜正相 Access Code | 有 | 有 |
| 搜反相 Access Code | **有** | **无** |
| 命中反相后整帧取反 | **有** | **无** |

你们自己的 `check_raw_file.py` 已经写过：录波里可能出现**极性翻转**的 Access Code。  
干扰链做了双搜，信息链没做——这是直接的代码级不一致。

**影响：** 若 Pluto/`gfsk_demod` 输出 0/1 反了，干扰仍可能解，信息会“完全看不见帧”。

---

### 缺陷 C【致命】信息波“无 Header 校验就灌缓冲”破坏拼包

`info_decoder_auto3.py`：

```text
模糊匹配后 48 bit Access Code → 回退 16 bit → 直接把 [12:27] 15 字节塞进 serial_buffer
注释写“不再检查 Header”
```

而 `replayer.py`（离线）反而有 Header 校验；实时信息波把这道闸拆了。

开源则是：Access（可模糊）→ **Header 必须为 15/15** → 才收 Payload。

**影响原理：**

- 假 Access 命中会把噪声当 Payload 灌进长流；  
- 干扰波：假数据大多过不了“整帧在 15 字节内 + CRC”，偶尔脏一下还能靠下一包；  
- 信息波：脏字节插在 9 包长流中间 → 后续所有跨包 CRC16 全灭。

**建议：** 实时信息波恢复 `00 0F 00 0F`（或 LE 变体）校验；模糊策略改用 Hamming 距离，而不是砍掉前 16 bit。

---

### 缺陷 D【严重】把“单包友好”算法原样套到“多包业务”上

两边都是：

```text
find(Access) → 切 15B → serial_buffer.extend → find(0xA5) → CRC8/CRC16
```

这对 `0x0A06`（15 字节整帧）很合适。  
对信息波，开源额外做了：

1. 只拼接**校验过的**空口包；  
2. 在长流上扫完整裁判帧；  
3. partial 扫描：即便不是完美连续 135 字节，只要某段 CRC+字段合理也用。

你们信息波缺少第 1、3 点 → 现场误码稍高就归零。

---

### 缺陷 E【严重】信息波物理层参数更“冲”、缺频偏/时钟余量

| 参数 | 你们信息波 | 开源默认 | 问题 |
|------|------------|----------|------|
| `gain_mu` | **0.3** | **0.175** | 时钟环过猛，易抖、易失锁 |
| `freq_error` | **0.0** | **0.0048** | 未预留采样率/晶振偏差 |
| 低通 | **300 kHz** | 信息约 **260 kHz**（且与整条链匹配） | 截止接近 Δf≈250 kHz，余量小 |
| 采样 | 直接 1 Msps + `gfsk_demod` | 2.083 Msps→重采样，或离线专用链 | 开源对弱信号更稳 |

干扰波你们 `gain_mu` 同样是 0.3，但信号强，环路误差被“淹没”。  
信息波 -60 dBm 时，同样参数会放大失锁。

---

### 缺陷 F【严重】信息波 Pluto 仍挂着 TX Sink

`competition/info/tx_radio.py` 同时连接了：

- `pluto_source`（收）  
- `pluto_sink`（发）  
- 还有 `gfsk_mod` ← UDP

即便业务上不发有效数据，**同机 TX 通路开启**也会抬高底噪/自干扰。  
对 -60 dBm 信息波几乎是自杀；对 -10 dBm 干扰波可能仍“看起来能用”。

**建议：** 比赛接收用 flowgraph 去掉 sink/mod，或 ENSM 强制 RX-only（开源有 `pluto_ensm.py` 思路）。

---

### 缺陷 G【中等】阵营/频点语义在干扰链上容易绕晕

规则（旧版同样）：

> 红方广播源/干扰源放在**红方雷达基座**，携带**蓝方**信息/密钥；蓝方反之。

因此：

- 己方是红 → 听 **红方频点**（己方基座上的发射源）才能拿到对方情报/密钥。  
- 开源：`--team red/blue` = **己方颜色 → 己方频点表**。  
- 你们信息波：`MY_CAMP` / `/team` → `INFO_FREQ_MAP[己方]`，**方向正确**。  
- 你们干扰波：`enemy_camp = 'BLUE'` 再去扫 `FREQ_MAP['BLUE']`，语义是“按敌方颜色选频”，**与规则几何相反**；虽在 BLUE 列表末尾塞了红方频点当兜底，但会先扫错频，表现为“不稳定、偶发成功”。

双 SDR 并不免除这个问题：两台都该锁**己方基座**对应频点。

---

### 缺陷 H【中等】模糊 Access 策略假阳性更高

| | 你们 | 开源 |
|--|------|------|
| 模糊方式 | 丢掉前 16 bit，后 48 bit 精确匹配 | 全 64 bit，允许 Hamming≤2 |
| Header 门闩 | 信息波实时路径关闭 | 始终开启 |

丢掉前 16 bit ≈ 承认更多“长得像”的噪声片段；信息波再叠加无 Header 校验，假包率更高。

---

### 缺陷 I【次要】缺少诊断与 partial 回退

开源会输出：

- Access Code 最小汉明距离  
- air_packets / referee_frames 计数  
- CRC8 模式  
- partial 帧与字段合理性  

你们信息波只有 5 秒 `0x0A0x` 计数。  
计数为 0 时无法区分：没信号 / 极性反 / 增益不够 / 拼包被污染。

## 4. 架构差异：双 SDR vs 单 SDR（不是根因）

| | 开源 | 你们 |
|--|------|------|
| 硬件 | 1×SDR 时分 jam/info | 2×Pluto 并行 |
| 优点 | 省设备、参数集中 | 信息波可常驻，不丢 10Hz 推送 |
| 缺点 | 切 info 窗口短（0.75s 级） | 两套参数易漂移、易不一致 |

**信息波解不出，主因不是“用了两套 SDR”，而是信息链路在增益、极性、Header、拼包容错上弱于干扰链路。**  
双 SDR 反而更适合信息波——修好 info 这一路后，理论上应比单 SDR 时分更稳。

## 5. 缺陷如何共同导致“只解干扰、不解信息”

```text
信息波 -60 dBm
    → gain 只有 27 + 可能 TX 自干扰
    → SNR 差、误码高
    → 若再遇极性翻转且信息链无双搜
    → Access 命中少 / 假命中多
    → 无 Header 门闩，脏 Payload 灌进长流
    → 需要连续 ~9 个正确包才能出一轮完整业务
    → CRC16 几乎全失败
    → 统计全 0

干扰波 -10 dBm
    → gain 40，信号强
    → 有极性双搜
    → 整帧塞进 1 个 Payload，脏包易被 CRC 挡掉
    → 偶发 1 个好包即可出密钥
```

## 6. 旧版规则下的优先整改顺序（不改架构）

1. **信息波增益**提到 ≥35，确认频谱能看到 433.2/433.92 峰；关掉 info 的 Pluto TX。  
2. **信息解码移植干扰链的极性双搜**（正/反 Access + 整帧取反）。  
3. **恢复 Header=`000F000F` 校验**后再 `extend` Payload；模糊改 Hamming。  
4. **放软时钟环**：`gain_mu≈0.175`，`freq_error≈0.0048`；评估 LPF 是否过窄。  
5. **干扰频点改回己方颜色表**（与信息波一致），去掉“敌方颜色”语义。  
6. 增加诊断：AC 命中数、Header 通过数、拼包后 CRC 失败数、极性选择。  
7. （进阶）移植开源 partial frame / 按包列表重组，而不是纯字节池。

参数口径继续保持旧版：SPS=52，广播 Sens=1.5756，等——先把旧版跑通，再升 V2。

## 8. 一句话总结

开源仓库与你们一样基于**旧版射频参数**；它能同时稳住干扰与信息，靠的是：  
**弱信号足够增益、极性自适应、Header 门闩、多包可靠重组、以及为信息波单独优化的解调参数。**  

你们干扰波碰巧踩中了“强信号 + 单包帧 + 极性双搜”；  
信息波则在 **增益、极性、Header、拼包** 四处同时薄弱——这才是解不出的根因，而不是“双 SDR 不行”。
