# 信息波 f6 近最优接收设计与调试

## 目标

在 **不改官方空口参数**（SPS=47、Sens=1.5628、Access/Header/CRC/ROS）的前提下，尽量逼近 PlutoSDR + GNU Radio 3.8 工程可行上限：

- 可观测物理量闭环（IQ 削顶 / CFO 估计）
- 匹配滤波 + `symbol_sync(M&M+MMSE)`
- soft 符号上的 Access 相关同步
- 连续 AGC + 离散 FIR 档兜底
- IQ 录波与离线回放

## 文件

| 文件 | 作用 |
|------|------|
| `competition/info/tx_radio6_flow.py` | 物理层主图 |
| `competition/info/tx_radio6.py` | 接收入口 |
| `competition/info/tx_radio6_tunes.py` | 档位 / AGC 限幅 |
| `competition/info/info_decoder_f6.py` | 解码 + 自适应 |
| `competition/info/info_f6_iq_replay.py` | IQ 离线回放 |

## 物理层链路

```text
Pluto 1Msps
→ [complex DC 可选]
→ channel FIR（可热更新）
→ QuadDemod(1/Sens)
→ 慢偏置扣除（single_pole_iir, α≈1e-5，τ≫Header连续0）
→ Gauss 匹配滤波（BT=0.35）
→ symbol_sync(M&M+MMSE) 或回退 clock_recovery_mm
→ soft float UDP :14347
→ hard bit  UDP :14346
→ 探头：IQ / FM / soft
→ 可选 IQ file_sink（tx_radio6.py 的 IQ_RECORD_PATH）
```

## 启动

默认自适应（一条命令，不需要任何环境变量，会自动拉起 `tx_radio6.py`）：

```bash
python3 competition/info/info_decoder_f6.py
```

比赛保守固定档：把 `tx_radio6_tunes.py` 的 `BOOT_PROFILE` 改成 `"fixed_balanced"`，
再把 `info_decoder_f6.py` 的 `ENABLE_AUTO` 改成 `False`，然后照样一条命令启动。

录 IQ：把 `tx_radio6.py` 的 `IQ_RECORD_PATH` 从 `None` 改成路径字符串，
例如 `IQ_RECORD_PATH = "/tmp/info_f6.c64"`，然后正常启动。
注意 1MHz 复数采样约 8MB/s，别录太久。

离线回放：

```bash
python3 competition/info/info_f6_iq_replay.py /tmp/info_f6.c64
```

不要与 f3/f4/f5 同时占用 Pluto、UDP 14346/14347、RPC 8081。

## 自适应逻辑（摘要）

每 2s：

1. 读 `get_iq_stats` / `get_fm_stats` / `get_soft_stats`（三个探头都必须读空，
   漏读的 vector_sink 会以约 200 kB/s 无限吃内存）
2. **确认持续削顶**才降增益：要求“到轨样本占比 `clip_frac ≥ 1e-3`”且峰值贴满量程，
   或者 RMS 已经高到 0.45。单个瞬时 `max_abs` 冲高不再算削顶——脉冲干扰会让旧逻辑
   误判，然后一路把增益降到 25 dB，弱信息波直接消失。
3. 没削顶就把 IQ 的 RMS 往目标区间 **0.08 ~ 0.30**（满量程占比）推：低于下限加增益，
   高于上限减增益，单次不超过 3 个 AGC 步长。增益上限放宽到 **60 dB**。
4. 有有效帧 → `locked`，保持不动
5. 探头确认削顶**且** AGC 已经降到底 → 才动用 `desense` 档（会 flush）
6. AC 有、Header 无 → `wide_fir` / `weak_boost`
7. Header 有、帧无 → 沿增益阶梯往上爬一格
8. 否则按档位表轮换；Access 假同步多时收到 2

## 软/硬双路径的铁律

硬比特就是软符号的符号位，两条路径解的是**同一串符号**。所以任何时刻**只允许一条
路径**往 `serial_buffer` 供货，另一条清空缓冲待命：

- 默认走软相关路径；连续 `PATH_FALLBACK_SILENCE_S`（默认 5s）颗粒无收就切到硬路径，
  反之亦然，切换时会清空字节河与包窗口。
- 若两条路都灌，字节河会变成 `P1软 P1硬 P2软 P2硬…`，15 字节的 Payload 被整段重复
  插入，跨 Payload 的裁判帧必然错位、CRC16 永远算不过。自检里有一条
  `单路径守恒` 用例专门锁死这个回归。

## 软相关阈值

`SOFT_CORR_MIN` 是**归一化相关系数**（0~1，默认 0.60），与信号幅度无关：
`ρ = <soft, 模板> / (|soft|·|模板|)`。旧版用未归一化的点积（满分约 64），信号一弱分数
就整体塌下去，同一个阈值时高时低完全没法用。

调法：日志里 `softAC` 一直是 0 就调低到 0.45~0.50；`softAC` 很多但 Header 全废就调高
到 0.70~0.75。别低于 0.4——64 个符号的纯噪声相关标准差约 0.125，再低就淹在误报里了。

## 验收矩阵

| 场景 | 期望 |
|------|------|
| 连续 420B 自检 | 硬/软/Header/CRC 全过 |
| -40 dB + -10 dB 干扰 | 帧率不低于稳定 f3 balanced（±10%） |
| -60 dB + -10 dB 干扰 | 不低于最佳 f4/f5 固定档；增益不过度顶平 |
| 人为高增益 | 数秒内 AGC 下降，日志出现 `agc:clip` / `probe-clip` |
| 同段 IQ 回放 | softAC/Header 趋势与在线可对照 |

## 明确不做

- 无 FEC 时软猜 Payload 并发布
- 短窗判决域 `dc_blocker` 默认开启
- 抄开源 SPS=52 / 单 SDR 时分架构
- 第一期多 `air_bit_order` 枚举

## 与 f5 关系

f5：离散换档 + 硬判决 + symbol_sync。  
f6：探头真值、连续 AGC、匹配滤波、软 Access、IQ 复盘。赛场可把 `ENABLE_AUTO` 改成 `False`，接近固定接收机行为。
